# Python RPG 设计系统

## 产品表面
产品包含 VS Code 左侧原生 Python 编辑器、右侧游戏 Webview，以及仅用于开发预览的浏览器应用。原生编辑器负责写代码；游戏表面负责任务、战场、提示、反馈和结算。

## 美学方向
延续“本地战术仪器”的工业奥术风格：结构严谨、信息可扫读、战场具有蓝图感。视觉服务回合决策和 Python 学习，不使用娱乐化装饰干扰代码与反馈。

## 设计 token
Webview 通过 CSS 自定义属性定义背景、表面、深层表面、边框、正文、弱化文字、主色、危险、成功、警告、单位和地形颜色。浅色、深色只替换 token；`system` 读取 VS Code 主题并映射到同一 token。正文使用 VS Code 界面字体变量，代码使用 VS Code 等宽字体变量。

## 布局策略
VS Code 工作区左右各约 50%。右侧页面固定为状态栏、任务条、弹性战场、反馈区、操作栏五段。战场方格边长同时受可用宽度、可用高度、列数和行数约束，保持正方形并居中；接近最小尺寸时先压缩图例和留白。

## 组件与模式
- `GameHeader`：关卡、回合、行动者、Python 状态和主题选择。
- `MissionStrip`：始终显示目标和失败条件。
- `BattleGrid`：完整显示当前地图，单位和目标带文字标签。
- `GuidanceDrawer`：分组提示，默认收起，错误时展开相关组。
- `FeedbackPanel`：运行输出、诊断和战斗事件。
- `ActionBar`：只保留当前阶段可执行的主要操作。

## 状态覆盖
连接/检测中显示局部加载说明；Python 不可用和代码错误提供修复动作；运行中锁定重复运行并显示中断；成功显示回合结果；空反馈说明等待运行；结算态显示下一关或重试。

## 记忆点
战场是半屏内自动伸缩的正方形蓝图矩阵，小地图放大、大地图缩小，始终完整可见。

## 动效策略
只使用 100–200ms 的状态淡入、按钮反馈和提示展开。所有过渡可中断，并在 `prefers-reduced-motion: reduce` 下关闭。

## 无障碍要求
正文对比度至少 4.5:1；交互元素有可见焦点；按钮和折叠区键盘可达；状态同时使用文字和颜色；战场提供网格、格位、单位和目标的辅助技术标签。

## 内容语气
使用直接、可执行的教学语言。错误说明包含位置、原因和下一步修正。按钮使用“运行回合”“中断运行”“重试本关”“进入下一关”等动作短语。

## 禁止事项
不使用默认紫白渐变、白底卡片堆砌、emoji 图标、全页 spinner、仅靠颜色传达状态或覆盖 VS Code 原生编辑体验。

## 约束定义
核心页面最多五个纵向区块；同一状态最多一个主按钮；常驻强调色不超过两种；战场不出现横向滚动；不为六关之外的超大地图加入缩放工具。

## 实现备注
Webview token、布局和组件样式位于扩展 `media/`；消息和视图快照类型位于共享 TypeScript 模块；主题偏好由扩展存储，Webview 只发送选择。视觉验收至少覆盖 1280×800 的左右半屏浅色、深色，以及第二关 4×3 和第六关 6×4 战场。
