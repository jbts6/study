1. 用 Python 独立编写数据处理脚本，熟练使用 numpy/pandas 完成数据清洗与特征工程

## 常见卡点

| 卡点 | 解决方案 | 前端类比 |
|---|---|---|
| 缩进即作用域报错 | 编辑器启用 Black/ruff 自动格式化，缩进错误会直接 SyntaxError | JS 用花括号，Python 用缩进 |
| 可变默认参数陷阱 | def f(x=[]) 会在多次调用间共享列表，改用 None + 内部判断 | JS 默认参数无此问题 |
| 列表 vs numpy 数组混淆 | 纯 Python list 做数值计算极慢，数据处理一律用 numpy/pandas | JS Array 是动态的，numpy 数组是固定类型 |
| 数学公式看不懂 | 先看 3Blue1Brown 可视化建立直觉，再回看公式，不要硬啃 | 前端通常不接触线代/微积分 |
| 张量形状不匹配报错 | 养成 print(tensor.shape) 的习惯，对标 console.log 调试 | 对标前端打印数据结构 |
| 模型不收敛 | 先检查数据是否标准化，再调学习率（从 0.001 开始试） | — |
| 过拟合（训练好测试差） | 加正则化 / Dropout / 数据增强 / 早停，三板斧轮着试 | — |
| 包管理混乱 | 每个项目独立 venv，不要全局装包 | 对标 npm 的 node_modules 隔离 |

## 动态调整说明

- 若数学基础较好（理工科背景）→ 压缩阶段 2 数学补课至 2 周，省下时间投入深度学习实战
- 若每周投入降至 8 小时以下 → 总周期延长至 7-8 个月，各阶段天数按比例放大，优先保证数学和 ML 基础不动
- 若目标偏向工程而非研究 → 阶段 3 减少理论推导，增加模型部署（FastAPI/Docker）和 MLOps 内容，深度学习聚焦调用预训练模型
- 若目标是做 LLM/大模型应用 → 阶段 4 调整为 HuggingFace Transformers + Prompt Engineering + RAG 实战，而非从零训练
- 若阶段 1 Python 语法学得快（1 周搞定）→ 将多出的一周前移到阶段 2 数学补课，数学是最大瓶颈
