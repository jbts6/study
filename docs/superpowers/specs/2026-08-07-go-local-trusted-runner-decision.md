# Go 本地可信执行模式

日期：2026-08-07

## 背景

Go 交互式课程的当前使用场景是单人本机自学，用户运行自己的练习代码，不把服务暴露给不可信用户或公网。原方案以 Docker 作为强制隔离边界，带来了 Docker Desktop 的额外内存和启动开销。

## 决策

课程服务默认使用宿主机 Go 工具链执行练习代码。每次执行仍写入独立临时目录，服务端选择隐藏测试，保留代码大小、合并输出大小和执行时间限制。

Docker 执行器继续保留为显式的 `--runner-mode docker` 模式，用于以后需要运行不可信代码的场景；默认的 `--runner-mode local` 不宣称提供安全沙箱能力。

## 影响

- 本机自学不再要求安装或启动 Docker Desktop。
- 宿主机模式可以复用本机 Go 编译缓存，降低单次执行的资源开销。
- 本机模式不适合公开部署、多用户服务或执行陌生代码。
- Docker 模式的隔离约束和集成测试继续保留，不影响后续重新启用隔离执行。
