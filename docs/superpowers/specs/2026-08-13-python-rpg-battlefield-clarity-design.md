# 蓝图战场目标导向 UI 设计

## 目标

让第一次进入关卡的玩家在首屏先理解“这关要完成什么”，再知道目标在战场哪里，最后知道需要编辑并运行哪段 Python。保留现有单屏布局、战斗状态源和底部反馈结算，不新增页面或独立 UI 状态。

## 设计决定

- 战场标题区显示当前关卡任务名、目标摘要和失败约束。
- 标题下显示当前行动提示，文案明确当前单位和下一步“编辑 choose_turn 并运行回合”。
- 战场上方显示文字图例：主角、敌人、关键目标、可激活目标、危险格、阻挡格；信息不只依赖颜色。
- 单元格坐标保留为辅助信息，弱化视觉权重；单位和目标标记提升层级。
- 关键目标显示耐久与保护语义，非关键目标显示激活进度；与右侧任务清单使用同一套状态文字。
- 右侧简报仍提供完整目标、能力冷却、API 速查和概念提示，但目标清单增加“进行中/已完成”语义。
- 运行按钮保持代码区底部主操作，旁边显示当前操作提示；运行中、错误和结算状态沿用现有反馈区。

## 实现边界

- 修改 `rpg/src/app/app-view.ts` 的静态结构与战场/简报渲染。
- 修改 `rpg/src/styles/game.css`、`layout.css`、`responsive.css` 的层级、图例、目标标记和响应式布局。
- 不修改战斗类型、控制器、存档、Runner 或战斗规则。

## 验收

- 首屏可见任务名、至少一条目标摘要、失败约束和当前行动提示。
- 图例包含六类战场元素，且不依赖颜色单独传达含义。
- 关键目标和可激活目标在格子内显示可读状态；目标清单显示完成状态。
- 现有结算按钮、普通错误反馈和运行流程不回归。
- `npm test -- src/app/app-controller.test.ts` 与 `npm run build` 通过。
