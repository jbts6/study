# Python RPG 阶段 3 应用外壳设计

## 结论

阶段 3 交付一个桌面端单屏应用外壳。玩家在本机浏览器的 CodeMirror 中编写 Python，通过 `127.0.0.1` 回环连接交给本地 Runner，再由本机 CPython 子进程执行。代码不离开本机，浏览器不执行 Python。

应用层只保留一个状态源 `AppController`。它串联 Runner、战斗内核、存档和被动 UI。首个遭遇使用现有战斗夹具；玩家只控制友方，敌方回合自动执行预设的 `wait`。阶段 3 不建设 AI、战役内容系统、移动端适配或通用状态框架。

## 目标

- 显示战场、回合信息、Python 编辑器、运行与中断控件、执行反馈。
- 玩家能够编辑 Python，并用本机 CPython 执行一个友方回合。
- 有效指令立即提交；失败运行不推进战斗。
- 自动推进敌方预设回合，直到再次轮到友方或战斗结束。
- 使用单份 V1 `localStorage` 存档恢复关卡、战斗和代码草稿。
- 刷新后继续战斗，并完成一个单遭遇。

## 非目标

- 六关战役、奖励、解锁、隐藏断言和关卡加载器。
- 敌方 AI、行为树或通用敌方策略系统。
- Pyodide、WASM、远程代码执行或云端存档。
- 窄屏、移动端和多视口适配。
- 存档迁移、双代备份、校验和、自动修复和导入导出。
- 事件总线、第二套 reducer、通用状态库和 UI 框架。
- Runner 内部重启状态机、进程竞态矩阵和额外生命周期测试。

## 本地代码边界

代码路径固定为：

```text
本机浏览器 CodeMirror
        ↓
AppController
        ↓
ws://127.0.0.1 回环连接
        ↓
本机 Node Runner
        ↓
本机 CPython 子进程
```

强制约束：

- 游戏页面与 Runner 只监听 loopback 地址，不监听 `0.0.0.0`。
- Python 代码不发送到远程服务。
- 浏览器不使用 Pyodide 或 WASM 执行 Python。
- CodeMirror、字体和脚本本地打包，不加载 CDN、分析服务或远程 API。
- 代码草稿只写入本机浏览器 `localStorage`。
- Runner 继续使用模块白名单，避免 `socket`、`ssl`、`http`、`subprocess` 等误操作。
- 采用信任本地代码模型，不把工作目录隔离和进程隔离描述为恶意代码安全边界。

## 应用架构

### AppController

`AppController` 是唯一应用状态源，持有：

- 当前关卡 ID。
- 当前 `BattleState`。
- Python 代码草稿。
- Runner 展示状态。
- 最近一次执行反馈。
- 损坏存档状态。

公共操作：

```ts
start(): Promise<void>
setCode(code: string): void
runTurn(): Promise<void>
interrupt(): Promise<void>
resetSave(confirmation: string): void
subscribe(listener: (snapshot: AppSnapshot) => void): () => void
getSnapshot(): AppSnapshot
```

### 注入依赖

- `RunnerClient`：连接、运行、执行中断和报告连接状态。
- `SaveStore`：读取、保存和重置单份版本化存档。
- 初始遭遇工厂：创建 `python-marsh-01` 的初始战斗状态。
- 敌方预设指令函数：阶段 3 对启用的敌方返回 `wait`。

`main.ts` 只创建具体依赖、启动控制器并挂载 UI。CodeMirror 与 DOM 不持有独立业务状态，只将用户操作转交给控制器，再按 `AppSnapshot` 渲染。

## 回合数据流

运行流程固定为：

1. 冻结当前代码快照。
2. 从当前 `BattleState` 生成只读 `WorldView`。
3. 将代码与 `WorldView` 交给本地 Runner。
4. Runner 返回候选 `TurnCommand`。
5. `resolveTurn` 校验并执行友方指令。
6. 若指令有效，更新战斗状态。
7. 自动执行敌方预设指令，直到再次轮到友方或战斗结束。
8. 保存新的战斗状态与当前代码草稿。
9. 发布回合摘要与战斗事件。

Python 错误、Runner 错误或非法指令只更新反馈，不修改战斗状态和已保存的战斗进度。

## Runner 展示状态

UI 只呈现四种状态：

| 状态 | 编辑器 | 运行按钮 | 中断按钮 | 玩家提示 |
|---|---|---|---|---|
| 连接中 | 可编辑 | 禁用 | 禁用 | 正在连接本地 Runner |
| 可运行 | 可编辑 | 启用 | 禁用 | 可以运行本回合 |
| 运行中 | 只读 | 禁用 | 启用 | 正在执行当前代码快照 |
| 不可用 | 可编辑 | 禁用 | 禁用 | 显示本地 Runner 启动提示 |

内部重启、进程代际和 WebSocket 生命周期不扩展成 UI 状态。

## 反馈与错误处理

- 成功：显示移动、伤害、状态变化和敌方回合摘要。
- 语法错误：显示 Python 行号和诊断，战斗不推进。
- 运行时错误：显示异常类型与可读信息，战斗不推进。
- 超时：说明执行超时，战斗不推进，恢复后可再次运行。
- 中断：显示“运行已中断，回合未推进”，保留草稿和战斗状态。
- 非法指令：展示战斗内核返回的具体错误，战斗不推进。
- Runner 不可用：保留并继续保存草稿，提示启动本地 Runner。

反馈区使用可访问的实时消息区域。标准输出、错误诊断和回合摘要在同一反馈面板中分区展示，不弹出多层对话框。

## 初始代码

首次进入时提供可编辑脚手架和简短 API 提示，不提供关键战术答案。脚手架包含入口结构、世界读取方式和一个需要玩家替换的 `wait` 示例。

## 存档设计

唯一存档键为 `python-rpg.save`：

```ts
type SaveDataV1 = {
  version: 1;
  currentLevelId: "python-marsh-01";
  battleState: BattleState;
  codeDraft: string;
};
```

保存时机：

- CodeMirror 内容变化后保存最新代码草稿。
- 友方与自动敌方回合全部成功后保存新战斗状态。
- 失败、非法指令、超时和中断不修改战斗状态。
- 每次保存覆盖同一个键，不保留历史版本。

读取只检查 JSON、V1 版本、关卡 ID、代码草稿和战斗状态的必要字段。解析失败、字段错误或版本不支持时进入损坏存档恢复状态，不自动修复或迁移。

任何重置都使用文本确认。玩家必须在执行前输入完整的“重置存档”；只有完全匹配后才允许删除并重建初始 V1 存档。该规则同时适用于正常存档和损坏存档恢复页，不使用普通二次点击确认。

## 桌面 UI

视觉方向为“奥术工业控制台”：

- 深铁蓝作为工作台背景。
- 黄铜用于结构、刻度和主要动作。
- 青蓝用于法术轨迹、当前单位和可运行状态。
- 低饱和赤红用于危险和错误。
- 战场使用蓝图网格和坐标刻度，形成“代码驱动战术仪器”的记忆点。

目标视口为 1280×720 及以上。页面采用三层布局：

1. 顶部状态轨：产品名、关卡、回合、当前单位和 Runner 状态。
2. 中部双主区：左侧战场与回合信息，右侧 CodeMirror 与运行控件。
3. 底部反馈区：标准输出、诊断和回合摘要。

单屏只有一个主要动作“运行回合”。“中断运行”只在执行期间出现。重置存档使用弱化危险操作入口，不与主要动作竞争。

阶段 3 不实现窄屏断点和移动端布局，也不维护多视口截图矩阵。

## 可访问性与动效

- 正文对比度至少 4.5:1。
- 所有控件键盘可达并具有可见焦点环。
- 状态同时使用文字与颜色表达。
- 按钮点击区域至少 44px 高。
- 战场单元格提供可读标签。
- 当前单位使用低频呼吸光，结果反馈使用短暂边缘脉冲。
- `prefers-reduced-motion: reduce` 下关闭非必要动效。

## 测试与验证

自动化只保留：

1. `AppController` 成功流程：有效指令更新战斗、自动执行敌方 `wait`、保存并发布反馈。
2. `AppController` 关键失败流程：Python 失败或非法指令不推进战斗和存档。
3. 损坏存档流程：无效 JSON 或必要字段缺失进入恢复状态；输入“重置存档”后创建新存档。
4. 一条真实 Playwright 主流程：启动本地 Runner 和游戏，编辑 Python、运行回合、验证战场变化，刷新后恢复，再完成单遭遇。

不增加移动端测试、组件快照测试、Runner 时序矩阵、存档迁移测试和所有错误类型的排列组合。

阶段完成时执行一次：

- `npm test`
- `npm run build`
- 桌面主视图人工视觉检查
- Runner 不可用人工检查
- 文本重置确认人工检查

## 阶段完成标准

- 在桌面浏览器启动游戏并看到战场、回合信息、编辑器和 Runner 状态。
- 玩家能够编辑并运行 Python，成功完成一个友方回合。
- 敌方预设回合自动推进，失败运行不改变战斗状态。
- 刷新后恢复代码和战斗，再继续完成单遭遇。
- 损坏存档只能通过输入“重置存档”恢复。
- 页面与 Runner 只监听 loopback，代码不离开本机。
- 控制器关键单测、唯一 Playwright 主流程、完整单元测试和生产构建通过。
