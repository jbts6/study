# Python RPG 浅色主题设计

## 结论

Python RPG 的整体界面改为 VS Code Light+ 方向的冷白工作台。页面使用浅灰背景、白色工作面板和清晰细边框；编辑器使用白底、浅灰行号区、蓝色光标与 VS Code Light+ 语法色。该方向优先解决长时间阅读疲劳，同时保留战场、任务、运行反馈的层级和 RPG 身份。

本次只重做视觉系统，不调整双栏布局、游戏流程、文案、Runner、存档或战斗逻辑。项目只保留一套浅色主题，不增加主题开关或额外依赖。

## 问题与目标

当前界面的问题不是单个颜色失衡，而是整个视觉系统同时使用深色背景、高饱和青色、高饱和语法色和发光阴影。编辑器占据主要阅读区域，这些效果叠加后会造成明显视觉疲劳，也让代码、战场和状态提示争夺注意力。

改版目标：

- 连续阅读和编辑 Python 时，编辑器保持稳定、清晰、不刺眼。
- 页面与编辑器属于同一个浅色工作台，不出现深浅色断裂。
- 战场仍比普通表单更具战术感，但不依赖霓虹和发光。
- 运行、危险、成功、失败和当前单位仍能快速识别。
- 保留现有信息密度和操作位置，避免视觉改版影响学习流程。

## 非目标

- 不提供深色/浅色切换。
- 不重新设计页面布局、导航或任务信息结构。
- 不新增插画、背景图片、粒子效果或外部字体。
- 不修改 CodeMirror 的编辑行为、快捷键和内容。
- 不为了视觉升级增加组件框架或主题库。

## 设计方向

界面采用“冷白战术工作台”。它借用 VS Code Light+ 的阅读习惯，但不是完整复制桌面编辑器外壳：代码区保持熟悉的编辑体验，战场和任务区使用同一套浅灰层次、蓝色交互强调和少量黄铜战术标记。

情绪目标是安静、精确、可持续阅读。记忆点是“代码工作台与战场蓝图共用一套浅色网格语言”：玩家写下的战术和左侧战场在视觉上属于同一台仪器。

## 色彩系统

### 基础表面

| 角色 | 颜色 | 用途 |
|---|---|---|
| 页面背景 | `#f3f4f6` | 应用最底层背景 |
| 主表面 | `#ffffff` | 状态栏、战场面板、编辑器面板、反馈面板 |
| 次级表面 | `#f6f8fa` | 行号区、任务简报、操作栏、禁用区域 |
| 悬停表面 | `#eef3f8` | 次级按钮悬停、可交互摘要悬停 |
| 边框 | `#d0d7de` | 面板、分区和输入框边界 |
| 强边框 | `#afb8c1` | 当前单元、聚焦前的结构强调 |

### 文本与强调

| 角色 | 颜色 | 用途 |
|---|---|---|
| 正文 | `#1f2328` | 标题、正文、代码默认文本 |
| 弱化文字 | `#57606a` | 说明、行号、元数据 |
| 主操作蓝 | `#0078d4` | 运行按钮、焦点环、当前单位、Runner 可用 |
| 主操作悬停 | `#106ebe` | 主按钮悬停 |
| 战术金 | `#8a6116` | 关卡标签、任务目标、掩体和目标点 |
| 成功绿 | `#1a7f37` | 成功反馈和完成状态 |
| 危险红 | `#c9362b` | 错误、危险格和重置操作 |
| 警告黄 | `#9a6700` | 失败约束和注意事项 |

正文与弱化文字在白色或浅灰表面上都必须保持足够对比度。蓝、绿、红、金只承担语义，不用于大面积背景。

## 页面结构

### 页面背景

页面底色为 `#f3f4f6`。保留极淡的正交网格作为战术仪器线索，网格颜色不超过 `rgba(31, 35, 40, 0.035)`。移除径向光晕、深色渐变和发光装饰。

### 顶部状态栏

状态栏使用白色实底和底部细边框。产品名使用深色正文；“本地战术仪器”使用战术金，不使用全大写高饱和色。状态项之间保留现有分隔线，Runner 可用状态使用主操作蓝，异常状态使用危险红。

阴影只用于区分固定层级，使用 `0 2px 8px rgba(31, 35, 40, 0.08)`，不产生悬浮卡片感。

### 主工作区与面板

保留左战场、右编辑器的双栏结构。两个主面板使用白色背景、`1px` 浅灰边框、`6px` 圆角和轻量阴影。面板标题区使用白色或次级表面，不使用渐变。

任务简报使用次级表面，和编辑器之间通过边框分隔。标题、目标、约束、能力和 API 速查继续按现有顺序展示，不增加徽章或额外容器。

### 战场

战场底色为 `#eef2f5`，使用低对比蓝灰网格。普通单元格为近白色，边框为 `#c8d1da`。

- 当前单位：蓝色左边框、浅蓝背景 `#e8f2ff`，不使用持续发光。
- 目标点和掩体：战术金边框或文字，保持小面积使用。
- 危险格：浅红斜纹背景 `rgba(201, 54, 43, 0.08)` 加危险红边框。
- 阻塞格：`#d8dee4` 实底，仍显示坐标。
- 单位条：白色或浅蓝表面，深色文字，避免黑底浮层。

活动单位可保留低频呼吸反馈，但只在边框颜色和浅蓝底之间变化，禁止外发光。

### 反馈与结算

反馈面板使用白色背景和左侧语义色边框。普通反馈为蓝色，成功为绿色，错误和失败为红色。正文保持深色，标准输出和错误输出使用等宽字体和次级表面，不使用深色终端块。

短促的边缘反馈动画可以保留，持续时间不超过 `360ms`；在减弱动效设置下关闭。

### 按钮与输入

- “运行回合”：主操作蓝实心按钮、白字；悬停使用更深蓝色。
- “中断运行”：白底蓝色边框与蓝字，仅在运行期间出现。
- “重置存档”：白底危险红文字，避免和主操作竞争。
- 对话框确认按钮：危险红实心按钮、白字。
- 普通按钮：次级表面、浅灰边框、深色文字。
- 输入框：白底、浅灰边框；聚焦时使用蓝色焦点环。

按钮保持现有至少 `44px` 高度。禁用状态降低对比度但仍可辨认文字，不只使用透明度表达状态。

## CodeMirror 编辑器

### 表面与结构

编辑器明确声明浅色主题：

- 内容背景：`#ffffff`
- 默认代码：`#1f2328`
- 行号区背景：`#f6f8fa`
- 行号：`#6e7781`
- 行号区分隔线：`#d0d7de`
- 当前行：`#f6f8fa`
- 当前行号：`#1f2328`
- 光标：`#0078d4`
- 选区：`#add6ff`
- 匹配括号：浅蓝底并使用 `#0078d4` 边框
- 只读状态：保持白底，通过光标和可编辑状态表达，不整体变灰

继续使用本地 `Cascadia Code` / `Consolas` 字体回退，不加载网络字体。字号保持 `14px`，行高设置为 `1.55`，内容区增加适度上下内边距。

### Python 语法色

语法色参考 VS Code Light+，同时降低连续阅读时的刺激：

| 语法角色 | 颜色 |
|---|---|
| 关键字、控制流 | `#0000ff` |
| 函数定义和调用 | `#795e26` |
| 字符串 | `#a31515` |
| 注释 | `#008000` |
| 数字 | `#098658` |
| 类型和类名 | `#267f99` |
| 属性名 | `#001080` |
| 运算符与标点 | `#1f2328` |
| 无效内容 | `#c9362b` |

不使用纯青、荧光绿、霓虹紫或大面积粗体。语法色只帮助扫描代码，不与错误反馈和主操作争夺注意力。

## 状态矩阵

| 状态 | 编辑器 | 主按钮 | 状态提示 | 反馈区 |
|---|---|---|---|---|
| 连接中 | 可编辑、浅色 | 禁用 | 弱化文字 | 普通蓝边 |
| 可运行 | 可编辑、浅色 | 蓝色实心 | 蓝色文字 | 普通蓝边 |
| 运行中 | 只读、浅色 | 禁用 | 蓝色文字 | 普通蓝边 |
| Runner 不可用 | 可编辑、浅色 | 禁用 | 危险红文字 | 红色边框与启动提示 |
| 回合成功 | 可编辑或结算只读 | 按流程决定 | 成功绿 | 绿色左边框 |
| Python/指令错误 | 可编辑 | 按流程决定 | 危险红 | 红色左边框与具体错误 |
| 战役结算 | 只读、浅色 | 隐藏或禁用 | 成功/失败语义色 | 对应语义边框 |

## 响应式与可访问性

桌面端继续以 `1280×720` 及以上为主要视口。现有 `1180px` 断点以下改为单栏，浅色主题不得改变布局行为。

- 正文对比度至少 `4.5:1`，大文字至少 `3:1`。
- 焦点环统一使用 `2px #0078d4`，并保留偏移。
- 状态必须同时有文字和颜色，不只靠色块。
- 战场单元继续保留可读标签。
- 所有非必要动画响应 `prefers-reduced-motion: reduce`。
- 在 `1440×900` 和 `1180×800` 两个视口检查文字截断、滚动和面板重叠。

## 实现边界

正式实现只涉及以下文件：

- `rpg/src/styles/tokens.css`：浅色基础与语义变量。
- `rpg/src/styles/layout.css`：页面背景、状态栏和布局表面。
- `rpg/src/styles/game.css`：面板、战场、反馈、按钮、输入和对话框。
- `rpg/src/app/code-editor.ts`：CodeMirror 浅色表面和 Python 语法高亮。
- `rpg/e2e/app-shell.spec.ts`：一条浅色关键计算样式回归检查。

不修改 `app-view.ts` 标记结构，除非视觉实现发现现有 DOM 无法满足可访问性或状态表达；这种情况必须先回到设计文档说明原因。

## 验收标准

- 页面加载后不存在深色全屏区域或深色编辑器区域。
- 页面背景为浅灰，状态栏、主面板和反馈区为白色或次级浅色。
- CodeMirror 内容区为白色，行号区为浅灰色，选区和光标清晰。
- Python 关键字、函数、字符串、注释和数字使用本方案规定的语法色。
- 当前单位、危险格、阻塞格、目标点可以在不依赖发光的情况下区分。
- 主操作、危险操作、成功反馈和错误反馈的语义不混淆。
- `1440×900` 桌面截图中无重叠、截断或异常强对比区域。
- `1180×800` 单栏边界截图中无横向溢出和文字遮挡。
- 相关 Playwright 视觉契约检查和生产构建通过。

## 与既有设计的关系

本方案只替代阶段 3 设计文档中“桌面 UI”章节的深铁蓝、黄铜主操作、青蓝霓虹和持续发光规定。阶段 3 的应用架构、布局层级、交互状态、可访问性目标和本地 Runner 契约继续有效；阶段 4 的战役内容与流程不受影响。
