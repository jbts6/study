# Python、Go、Rust 本地多语言学习工坊设计

日期：2026-08-17

状态：规格已通过；测试范围限定为核心主流程、一个关键失败路径和明确测试预算

## 摘要

本项目不再把六关 RPG 作为 Python、Go、Rust 学习体系的边界。仓库应演进为
一个本地运行的多语言学习工坊：Python 负责建立编程与快速反馈能力，Go 负责
建立静态类型、工程边界和并发能力，Rust 负责建立所有权、内存模型和精确建模
能力。

三门语言按顺序学习，不并行推进。统一的是学习路线、课程元数据、练习证据、
进度语义和执行结果；Python、Go、Rust 继续使用各自最合适的执行器。RPG 保留
为可选项目题材，不再承担全部教学目标。

第一阶段不重写三个课程前端，也不合并三个执行器。首个证明点是用同一份需求、
输入样例和验收标准，完成 Python、Go、Rust 三版日志分析工具，并验证学习者
能够解释三种实现的设计差异。

## 背景

仓库已经存在三条课程能力：

- python/ 当前只保留路线、资料和项目教程；README 中提到的 basics-course/ 不在工作树内，通用 Python 交互课程需要作为独立入口新建。
- go/interactive-course/ 提供课程目录、隐藏测试、本机 go test 执行和课节
  解锁。
- rust/interactive-course/ 提供 12 节练习、本机 cargo test 执行和浏览器
  进度状态。
- rpg/ 提供 VS Code 扩展、本地 Python 执行和项目化反馈场景。

这些实现已经证明本地课程、即时运行和测试反馈可行，但目前存在四个问题：

1. Python 缺少通用交互课程；现有 RPG Runner 的输入输出契约服务于战斗，不适合作为通用课程执行器。
2. Go、Rust 课程缺少共同的长期学习目标，完成课节不等于形成可迁移能力。
3. Python、Go、Rust 的课程来源、完成标准和进度语义各不相同。
4. 当前体系偏重“读完章节、通过隐藏测试”，独立重建和项目迁移不足。
5. RPG 题材对 Python 有价值，但无法自然承载 Go 和 Rust 的全部工程能力。

## 目标学习者

默认学习者能够安装本地工具、使用 VS Code 和运行终端命令，但不假定其已经掌握
计算机科学或任一目标语言。课程需要同时支持两类情况：

- 初学者按完整顺序学习 Python、Go、Rust。
- 已有经验者通过独立重建任务证明能力后跳过对应基础单元。

跳过只减少重复讲解和引导练习，不取消当前语言的独立项目，也不取消跨语言
复盘。

## 目标

- 建立一条 Python -> Go -> Rust 的顺序学习路线。
- 新建与 RPG 解耦的本地 Python 交互课程入口。
- 每门语言只保留一条主线课程、一组精选练习和一个独立项目。
- 通过回忆、测试、错误修复和项目迁移验证学习，而不是只记录阅读完成。
- 统一课程导航、元数据、进度证据和执行结果的含义。
- 保留语言专属工具链和诊断信息，不制造最低公分母式运行器。
- 用跨语言练习展示设计取舍，而不是重复刷三遍相同语法题。
- 全部能力面向单人、本机学习，不引入账号、云同步或公网代码执行。

## 非目标

- 不要求三门语言同时学习。
- 不把 30 Days of Python、Rust Book 或其他外部资料全文复制为自有课程。
- 不在第一阶段重写 Python、Go、Rust 三个课程前端。
- 不在第一阶段创建统一编译服务、容器平台或插件系统。
- 不把所有课节强制包装成 RPG 战役。
- 不以题目数量、课节数量或隐藏测试通过率作为唯一学习成效。
- 不为多人教学、教师后台、排行榜、证书或远程部署设计。

## 核心学习策略

### 顺序学习

学习者在一段时间内只使用一门主语言：

1. Python 建立编程思维、自动化、测试和快速交付能力。
2. Go 建立静态类型、包边界、接口、错误处理、并发和服务工程能力。
3. Rust 建立所有权、借用、枚举建模、错误类型、并发安全和系统边界能力。
4. 综合阶段比较三门语言如何解决同一类问题。

进入下一门语言前，学习者必须完成当前语言的独立项目。跨语言对照练习只在
当前阶段完成后出现，避免语法和工具链同时切换。

### 单课、练习、项目三件套

每门语言只配置：

- 一条主线课程：负责知识顺序和完整讲解。
- 一组精选练习：负责高频回忆和薄弱点修复。
- 一个独立项目：负责需求拆解、测试、调试和交付。

不把多个完整课程叠加。补充资料只解决明确缺口，不形成第二条并行主线。

### 学习时间分配

每周学习时间默认按以下比例分配：

- 20%：阅读、观看或查看示例。
- 70%：从空白文件实现、测试和修复代码。
- 10%：记录错误模式、设计取舍和下一次复习点。

每个核心概念在首次学习后的第 1、3、7、14 天安排短复习。复习任务要求重新
实现或修复代码，不要求重复阅读整章内容。

## 推荐课程主线

### Python

默认主线采用 University of Helsinki 的
[Python Programming MOOC 2026](https://programming-26.mooc.fi/)。
课程练习密度高，适合建立完整基础。

偏好视频讲解的学习者可改用
[Harvard CS50P](https://cs50.harvard.edu/python/)。
CS50P 包含十周内容、问题集和最终项目。两门课程二选一，不要求全部重复完成。

仓库现有 30 Days of Python 保留为参考和补充练习来源，不再作为唯一的能力
主线。

### Go

学习顺序为：

1. [A Tour of Go](https://go.dev/tour/)：用数天建立语言全貌。
2. [Learn Go with Tests](https://quii.gitbook.io/learn-go-with-tests)：
   作为主线，通过测试学习语言和工程边界。
3. [Exercism Go](https://exercism.org/tracks/go)：只选与当前薄弱点对应的练习。

### Rust

学习顺序为：

1. [The Rust Programming Language](https://doc.rust-lang.org/book/)：
   作为知识主线。
2. [Rustlings](https://rustlings.rust-lang.org/)：与 Rust Book 同步练习。
3. [Comprehensive Rust](https://google.github.io/comprehensive-rust/)：
   完成首个 Rust 项目后用于查漏补缺。

Comprehensive Rust 面向已有工程经验的学习者，不作为 Rust 零基础第一课。

### 外部课程使用原则

仓库保存课程路线、能力映射、自有练习和来源链接，不复制外部课程全文。外部
课程更新时，只检查受影响的能力映射和链接，不追求镜像其全部章节。自有练习
必须能够在没有外部课程网页的情况下运行和验收。

## 阶段与完成标准

| 阶段 | 建议时间 | 必须完成的能力证据 |
|---|---:|---|
| Python 基础与自动化 | 10 至 12 周 | 可独立完成带测试、文件输入输出和错误处理的 CLI |
| Go 工程与并发 | 8 至 10 周 | 可独立完成带测试、接口边界、并发和取消机制的本地服务或 CLI |
| Rust 系统建模 | 12 至 16 周 | 可独立完成使用所有权、枚举、Result、trait 和测试的本地工具 |
| 跨语言综合 | 4 至 6 周 | 可实现共同需求，并书面解释三种设计的收益与代价 |

时间基线按每周 8 至 10 小时计算。已有编程经验可以压缩练习数量，但不能跳过
独立项目和跨语言复盘。

## 教学单元设计

每个核心教学单元包含四类活动：

1. **理解**：简短讲解、可运行示例和明确目标。
2. **引导练习**：小范围修改代码，获得即时编译或测试反馈。
3. **独立重建**：从空白文件完成同类任务，不提供逐行骨架。
4. **迁移任务**：把概念用于新的数据、接口或业务约束。

课程内容可以提前浏览。前置关系用于标记推荐顺序和能力缺口，不使用硬锁阻止
学习者查看后续内容。只有“已掌握”状态需要独立任务证据。

隐藏测试只负责验证可确定的行为。课程必须同时显示公开验收条件，并保留真实
编译器、测试框架或运行时错误，避免学习者只能猜测隐藏断言。

## 掌握状态

每个教学单元使用四种状态：

- not_started：尚未开始。
- learning：已阅读或尝试，但未通过核心练习。
- practiced：已通过核心练习。
- mastered：已完成独立重建或迁移任务。

practiced 与 mastered 必须分开。通过一次带骨架练习不能直接视为掌握。

本地进度只保存恢复学习所需的信息：

- 当前状态。
- 最近活动时间。
- 下一次建议复习时间。
- 独立任务是否通过。
- 最近一次失败类型，用于恢复上下文。

首版不保存完整代码历史、逐次运行日志或复杂学习分析。

## 产品结构

### 推荐结构

~~~text
统一学习路线与进度
├── Python 课程入口
│   └── 本机 CPython + unittest 执行器
├── Go 课程入口
│   └── go test 本地执行器
├── Rust 课程入口
│   └── cargo test 本地执行器
├── 跨语言练习
│   └── 共享需求、样例数据和验收标准
└── 可选项目
    └── RPG、自动化工具、服务或系统工具
~~~

统一层只负责路线、元数据、进度和结果语义。语言入口继续负责编辑体验、工具链
检测、代码执行和诊断展示。

### 数据流

~~~text
课程目录
  -> 语言课程页面
  -> 学习者提交代码
  -> 语言执行适配器
  -> Python / go test / cargo test
  -> 标准化执行结果
  -> 页面显示原始诊断和课程提示
  -> 本地保存练习证据与复习时间
~~~

## 统一课程契约

课程元数据的最小公共字段为：

~~~json
{
  "id": "go-errors-01",
  "track": "go",
  "stage": "engineering",
  "title": "用显式错误表达失败",
  "objectives": ["返回并检查 error", "区分调用错误和领域错误"],
  "prerequisites": ["go-functions-02"],
  "activityTypes": ["guided", "rebuild", "transfer"],
  "sourceRefs": ["learn-go-with-tests"],
  "estimatedMinutes": 90
}
~~~

公共契约不保存语言专属测试源码。起始代码、示例、测试夹具和执行命令继续由
各语言课程目录管理。

## 统一执行结果

三种执行器对课程页面返回共同语义：

~~~json
{
  "status": "passed",
  "stdout": "",
  "stderr": "",
  "diagnostics": [],
  "checks": [
    {
      "name": "returns_invalid_record_count",
      "passed": true,
      "message": ""
    }
  ],
  "durationMs": 182
}
~~~

共同状态限定为：

- passed
- compile_error
- test_failed
- runtime_error
- timeout
- runner_unavailable
- invalid_request

语言适配器负责把工具链输出映射到共同状态，但页面仍显示清理本机绝对路径后的
原始诊断。标准化结果不能覆盖或改写真实错误。

## 首个跨语言证明项目

首个项目采用“本地日志分析工具”，三门语言共享：

- 一组固定的文本日志样例。
- 相同的输入参数和输出 JSON 结构。
- 相同的错误样例和验收数据。
- 相同的性能测量方法，但不设置语言排名。

三版实现分别强调：

- Python：数据转换、迭代速度、CLI 和测试。
- Go：并发读取、取消、错误汇总和包边界。
- Rust：类型化解析、所有权、错误枚举和内存使用。

学习者最后提交一份短复盘，回答：

1. 哪些约束在三门语言中应保持相同？
2. 哪些实现应遵循语言惯用方式而不同？
3. 哪种错误最容易在编译期发现？
4. 哪种实现最容易修改需求，原因是什么？

该项目同时验证教学迁移和统一课程契约。它不是性能竞赛，也不要求三版代码结构
一致。

## 导航与界面

第一阶段增加统一路线入口，但继续链接到现有三个课程应用。统一入口显示：

- 当前主语言和阶段目标。
- 本阶段主线课程、精选练习和项目。
- learning、practiced、mastered 三类进度。
- 到期复习任务。
- 跨语言项目仅在对应阶段完成后出现。

三个现有课程页面暂不统一视觉实现。只有公共契约经过真实课程验证后，才评估
是否提取共享前端组件。

## 错误处理

- Python 直接显示语法错误、异常类型、消息和用户代码位置。
- Go 直接显示编译错误、测试失败、竞态检测和超时信息。
- Rust 直接显示编译器诊断、借用检查错误、测试失败和超时信息。
- 工具链不可用时，明确显示缺少的程序、检测方式和安装入口。
- 课程提示只解释与当前目标相关的下一步，不隐藏原始错误。
- 运行失败不清除草稿或已保存进度。
- 进度存储损坏时恢复为空进度，并保留可阅读课程和代码运行能力。

## 测试策略

测试只保留服务于主学习流程的核心用例：

- 统一路线可加载目录、打开当前语言入口，并恢复一次本地进度。
- 每个新建或修改的语言执行器保留一条通过路径和一条最关键失败路径：Python 为语法或 unittest 失败，Go 与 Rust 为其现有执行器的核心失败状态。
- 首个跨语言项目只验证三版程序对共同夹具产生相同外部结果。

测试代码规模采用阶段预算，而不是按字段、状态或实现函数扩张：

- 每个独立能力默认只写一条成功路径和一条最可能阻断学习的失败路径。
- 第一份 Python 垂直切片最多包含 3 个测试文件、6 个自动化测试用例。
- 课程隐藏验收脚本也计入测试文件和用例预算，不单独排除。
- 不测试私有函数、简单字段转发、样式细节、重复关闭、极端竞态或未复现边界。
- 只有已经复现的真实缺陷可以突破预算；新增回归测试时优先合并或删除低价值测试。
- 实施计划必须在全量编码前声明本阶段测试文件数和用例数上限。

不建立完整课程契约矩阵、页面状态矩阵、跨平台版本矩阵、竞态矩阵或性能回归矩阵。
语言工具链只支持项目明确声明的当前稳定版本。

## 分阶段交付

### 阶段 1：统一路线和契约

- 定义课程元数据、执行结果和进度语义。
- 建立统一路线入口。
- 为现有 Python、Go、Rust 课程各映射一个代表性单元。

### 阶段 2：Python 主线

- 从 Helsinki MOOC 或 CS50P 中选定唯一主线。
- 将现有 30 Days of Python 降为补充资料。
- 补齐独立重建、迁移任务和 Python 独立项目。

### 阶段 3：Go 与 Rust 主线

- 按 Learn Go with Tests 重组 Go 的能力顺序。
- 按 Rust Book 与 Rustlings 重组 Rust 的能力顺序。
- 保留现有语言执行器，接入公共结果语义。

### 阶段 4：跨语言项目

- 加入共同日志夹具、需求和验收标准。
- 完成三版实现与设计复盘。
- 根据真实使用结果决定是否统一课程前端。

### 阶段 5：可选题材

- RPG 可作为 Python 项目或跨语言扩展题材。
- 其他题材包括自动化、数据处理、本地服务和系统工具。
- 题材不得反向决定全部课程结构。

## 成功标准

第一阶段成功需要同时满足：

- 学习者能从一个路线入口看到三门语言的顺序、目标和完成标准。
- 至少一个 Python、Go、Rust 单元使用公共课程元数据。
- 三种执行器对成功和关键失败返回一致的状态语义。
- 学习者可以区分“练习通过”和“已经掌握”。
- 首个跨语言项目具有共同输入、输出和验收夹具。
- 新增平台代码量没有超过新增课程和练习内容的代码量。
- 第一份 Python 垂直切片没有超过 3 个测试文件和 6 个自动化用例。

长期成功不以课节总数衡量，而以以下证据衡量：

- 学习者能从空白文件重建核心能力。
- 学习者能修复真实编译、测试和运行错误。
- 学习者能完成每门语言的独立项目。
- 学习者能解释同一需求在三门语言中的不同设计。

## 风险与止损

### 平台建设压过课程

如果统一路线需要先重写三个前端或合并三个执行器，立即缩小范围，只保留公共
元数据和导航页。

### 内容重复

如果主线课程和补充资料覆盖相同知识，保留练习质量更高的一项，删除重复必做
任务。

### 隐藏测试制造虚假掌握

任何只通过带骨架隐藏测试的课节最多标记为 practiced。没有独立重建或迁移
证据，不得标记为 mastered。

### 三语言上下文切换

默认界面只突出当前主语言。除短小对照练习外，不在同一周推进两门语言的新
概念。

### 统一契约过度抽象

如果三个代表性单元无法自然映射某个公共字段，优先删除该字段，不为表面对称
修改语言课程。公共契约只保留已经被三门语言共同证明的部分。

## 已确认决策

- 项目跳出六关 RPG，面向长期、多语言、可迁移的工程学习。
- 学习顺序为 Python -> Go -> Rust，不同时推进。
