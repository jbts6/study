# Go 交互式课程设计

## 目标

构建一个可在浏览器中学习 Go 的交互式课程站。用户在课程页面中编辑 Go 代码，提交后由服务端在隔离容器中运行 `go test`，并获得编译诊断、测试结果、标准输出和下一步提示。

第一版以一章可独立完成的 Go 入门课程验证完整学习闭环，不引入账号、云端进度、多语言课程或课程管理后台。

## 非目标

- 不实现宿主机直接执行用户代码的后备路径。
- 不允许浏览器提交或修改课程测试代码。
- 不在第一版实现任意 Go 项目、多文件上传或第三方依赖安装。
- 不把 GitHub 上的课程内容整库复制到项目中；仅借鉴课程组织、练习格式和测试反馈模型。

## 课程范围

第一章名为“Go 起步”，包含四节：

1. 输出与第一个 Go 程序：`package main`、`import`、`fmt.Println`。
2. 变量与基础类型：变量声明、类型、零值和字符串拼接。
3. 控制流：`if`、`for` 和简单的条件分支。
4. 函数与返回值：函数声明、参数、返回值，并用隐藏测试验证结果。

每节包含：

- 学习目标和短篇讲解。
- 可运行的初始代码。
- 一个明确的练习目标。
- 服务端保存的隐藏测试。
- 运行按钮、重置按钮和分级提示。
- 通过后才能解锁下一节的完成状态。

## 用户流程

1. 用户打开课程站，默认进入“Go 起步”第一节。
2. 页面展示当前知识点和可编辑的 Go 初始代码。
3. 用户点击运行，前端提交 `lessonId` 和代码内容。
4. 服务端校验请求并选择对应的隐藏测试，启动一次性隔离容器。
5. 前端展示运行状态、标准输出、编译诊断或测试差异。
6. 通过后保存本地进度，并允许进入下一节；失败时保留代码和提示。

## 界面设计

### 桌面布局

- 左栏：课程章节、当前节、完成状态。
- 中栏：讲解、代码编辑器和练习目标。
- 右栏：运行结果、测试列表、标准输出和提示。

右栏在运行时显示明确的加载状态，不使用遮挡整页的加载层。编辑器高度稳定，结果区不会因为输出变化导致布局跳动。

### 移动布局

课程导航、讲解、编辑器和运行结果按纵向排列。运行按钮保持可见，结果区紧跟编辑器下方；代码字体和点击区域使用响应式约束，避免横向溢出。

### 必须覆盖的状态

- 初始未运行。
- 正在运行。
- 通过。
- 编译错误，显示行号和错误信息。
- 测试失败，显示期望值和实际值。
- 执行超时。
- 执行服务不可用。
- 重置成功和按钮禁用状态。

## 技术架构

前端使用 TypeScript、Vite 和 CodeMirror，使用 Go 语言模式提供编辑器高亮和基本编辑体验。后端使用 Go 标准库提供 HTTP API，并负责课程内容读取、请求校验和执行任务调度。

```text
浏览器编辑器
    -> POST /api/execute
Go API 校验 lessonId、代码大小和请求格式
    -> 读取服务端课程测试
临时工作目录 + 隔离容器
    -> go test ./...
结构化结果
    -> 编译诊断 / 测试结果 / stdout / stderr
浏览器反馈与本地进度
```

### 课程内容存储

课程元数据和讲解使用版本控制下的结构化文件保存；每节课程的隐藏测试与课程 ID 一一对应。服务端只根据课程 ID 读取允许的测试目录，不接受客户端传入的测试路径。

### 本地进度

第一版只在浏览器 `localStorage` 保存已完成的课程 ID 和编辑器草稿。后端不保存用户身份、代码历史或运行记录。

## 在线执行器

每次执行创建独立临时目录，写入受控的 Go 源文件和服务端测试文件，然后启动一次性容器。容器必须满足以下约束：

- 使用固定版本或摘要锁定的 Go 工具链镜像。
- `--network=none`，禁止访问外部网络。
- 非 root 用户运行。
- 只读根文件系统，仅为临时目录和编译临时目录提供写权限。
- 限制 CPU、内存、进程数和最长运行时间。
- 删除全部额外 Linux capabilities，启用 `no-new-privileges`。
- 限制标准输出和错误输出大小，防止输出淹没服务。
- 禁止从用户代码加载外部模块；第一版只支持标准库和课程指定内容。

Docker 不可用时，API 返回明确的执行器不可用错误，不改为在宿主机运行代码。

## API 契约

### `GET /api/course`

返回第一章的章节、课程节、讲解内容、初始代码和提示。隐藏测试内容不出现在响应中。

### `POST /api/execute`

请求：

```json
{
  "lessonId": "go-start-01",
  "code": "package main\n\nimport \"fmt\"\n\nfunc main() {\n\tfmt.Println(\"Hello, Go!\")\n}"
}
```

响应：

```json
{
  "status": "passed",
  "stdout": "Hello, Go!\n",
  "stderr": "",
  "diagnostics": [],
  "tests": [
    {"name": "输出欢迎语", "status": "passed", "message": ""}
  ]
}
```

`status` 只允许使用 `passed`、`compile_error`、`test_failed`、`timeout`、`runner_unavailable` 和 `invalid_request`。诊断包含可选的 `line`、`column` 和 `message` 字段；服务端错误不返回容器内部路径或敏感环境变量。

## 测试策略

- API 单元测试：请求校验、课程 ID 映射、响应状态映射和输出截断。
- 执行器集成测试：正确代码、编译错误、测试失败、死循环和容器不可用。
- 课程契约测试：每节课程都有初始代码、隐藏测试和至少一个可通过答案。
- 前端组件测试：运行状态切换、诊断展示、通过后解锁和重置行为。
- 浏览器验收：桌面和移动视口完成第一节课程的完整流程。

## 验收标准

第一版完成必须满足：

- 用户可以打开课程站并看到第一章四节课程。
- 用户可以编辑 Go 代码并提交真实执行。
- 正确代码通过隐藏测试后显示成功并解锁下一节。
- 编译错误显示对应行号和可读信息。
- 测试失败显示期望值和实际值。
- 死循环在限制时间内结束并显示超时。
- Docker 不可用时显示明确错误，宿主机不会执行用户代码。
- 课程进度和草稿在刷新页面后仍保留。
- 关键流程在桌面和移动视口均无布局重叠或不可操作控件。
