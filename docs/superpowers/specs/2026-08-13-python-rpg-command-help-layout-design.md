# Python RPG 第一关命令提示区布局设计

## 目标

在保留完整命令契约提示的前提下，把编辑器作为右侧工作区的第一优先级。玩家打开第一关时应能直接看到并编辑 `choose_turn`，需要查字段格式时再展开提示，不被长段说明持续挤压。

## 已确认方向

采用 B 方案：编辑器优先 + 底部 API 提示抽屉。

### 默认状态

- 编辑器标题下只保留一行紧凑任务条。
- 任务条显示当前关卡目标、当前行动单位和回合限制；超出宽度时换行或截断，不展开成长段简报。
- `API 提示` 默认折叠，只占一行可点击摘要。
- 代码编辑区占据编辑器面板的主要剩余空间，运行按钮固定在编辑区底部。

### 展开状态

- 使用原生可访问的折叠控件展开 `API 提示`，焦点和键盘操作保持正常。
- 提示内容按四组呈现：命令外层字段、`movePath`、`action`、本关规则。
- `movePath` 组优先显示完整格式示例：`[{"x": 1, "y": 0}]`，同时保留错误示例 `[[1, 0]]` 和逐步移动限制。
- 抽屉设置固定最大高度；超过高度的内容只在抽屉内部滚动，不改变页面整体高度。
- 展开抽屉后运行按钮仍在当前视口内，编辑器保持可编辑和可聚焦。

## 页面结构

桌面端继续使用战场在左、编辑器在右的双栏结构。编辑器内部顺序固定为：

1. 编辑器标题
2. 紧凑任务条
3. 代码编辑区
4. API 提示抽屉
5. 运行操作栏

反馈区继续位于页面底部，不并入 API 抽屉。Python 运行错误、命令校验错误和结算状态沿用现有反馈组件，避免玩家在提示区和错误区之间寻找同一条信息。

移动端保持同一顺序：战场、编辑器标题、任务条、代码编辑区、API 提示抽屉、运行操作栏、反馈区。页面允许纵向滚动；抽屉内部仍有独立滚动边界。

## 信息层级

- 任务条只承担“现在要做什么”和“当前轮到谁”，不重复完整 API 文档。
- API 抽屉承担查阅，不承担持续提醒；默认状态不能占用代码阅读空间。
- 提示组内保留真实字段名、类型、层级、正确示例、常见错误示例和修复方向。
- 不修改命令协议、战斗校验、Runner 或存档数据。

## 状态与交互

- 加载/连接中：任务条保持可见，代码区和抽屉可读但运行操作按现有状态禁用。
- 运行中：编辑器按现有逻辑只读，抽屉可展开查看；运行按钮替换为中断操作。
- 命令错误：错误详情显示在底部反馈区，API 抽屉的展开状态不被强制改变。
- 胜利/失败：代码和提示可复盘，运行操作按现有结算规则锁定。
- 键盘：`Tab` 可到达抽屉摘要，`Enter`/`Space` 可展开或收起；焦点不跳离编辑器工作区。

## 响应式约束

- 桌面端默认收起时，任务条与 API 摘要合计不超过编辑器可视高度的约 15%。
- 桌面端展开高度不超过 `min(32dvh, 280px)`；内容超出时在抽屉内部滚动。
- 移动端展开高度不超过 `min(40dvh, 320px)`；代码区仍先于抽屉出现。
- 抽屉打开和关闭不能改变运行按钮的可达性，也不能造成页面横向滚动。
- 所有正文和字段示例保持足够对比度，不能依赖颜色单独传达合法/错误含义。

## 实现边界

- 修改 `rpg/src/app/app-view.ts` 的编辑器简报结构和提示抽屉渲染。
- 修改 `rpg/src/styles/layout.css`、`rpg/src/styles/game.css`、`rpg/src/styles/responsive.css` 的编辑器行、抽屉高度和响应式规则。
- 按现有测试结构补充默认收起、展开提示、错误反馈位置和移动端顺序的 UI 测试。
- 不修改 `BattleState`、命令校验、Runner、存档和战斗流程。

## 验收

- 第一关默认打开时，代码编辑区明显大于当前长提示堆叠布局，且任务条/API 摘要仍可见。
- 展开 API 抽屉后，四组提示和 `movePath` 正反示例可读；长内容在抽屉内部滚动。
- 展开/收起不改变运行按钮位置的可达性；错误反馈仍显示在页面底部。
- 桌面与移动端均无横向溢出，键盘可以操作抽屉，文字对比度清晰。
- `npm test -- --run src/app/app-controller.test.ts`、相关 UI 测试、`npm run build` 和浏览器截图验收通过。
